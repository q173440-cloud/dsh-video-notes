# 结构化笔记模板与 `save-note` 门禁规范

> **读取角色与时机**：仅由主会话在**所有切片子代理摘要均已回齐（且若有疑难帧已点读复核完毕）、准备撰写草稿与落盘保存**时读取。

## 1. 草稿写入、门禁保存与清理流程

1. 使用 `write_file` 将完整 Markdown 笔记写入临时草稿（例如 `./video-notes-data/episodes/<entryId>/note.draft.md`）。
2. 调用 `save-note` 执行严格门禁校验与原子落盘：
   ```bash
   ./dsh-video-notes/bin/video-notes save-note --entry-id "<stableId>" --status completed --title "<视频标题>" --content-file "<草稿文件路径>"
   ```
3. 保存成功后，删除临时草稿文件（如 `note.draft.md`）。
4. **缓存清理与缺口降级规则**：
   - `completed` 校验通过后，工具会自动安全清理 `work/` 媒体缓存（含自动合流生成的临时 `video_merged.mp4` 及 `work/slices/` 切片清单）。
   - 若存在无法弥补的画面遮挡、音轨缺失等严重缺口，必须标记为 `--status partial` 并通过 `--gaps-json` 说明，此时工具会保留恢复素材。

## 2. `completed` 完整笔记强制门禁要求

程序会在 `save-note` 时强制校验以下底线，不满足将被拒绝落盘：
- 必须包含 `# ` 与 `## ` 层级结构，正文不少于 150 字；
- 长篇笔记（> 500 字）必须包含：
  1. 至少 2 处 `[MM:SS]` 精确时间戳；
  2. 具体关键帧文件名引用（`frame_pts_...` / `关键帧`）；
  3. 明确区分客观事实与主观评价（包含“观点 / 评价 / 主观”区隔）。

## 3. 推荐固定章节结构

> 若视频涵盖多工具对比、多条目评测或装备选型，建议在“元数据”后紧跟“一屏速查总览表”，其余章节保持完整。

1. **元数据**：标题、来源链接/路径、视频规格、作者/UP 主、时长、字幕来源（平台字幕 / 本地 ASR）、抽帧参数。
2. **（按需）一屏速查总览**：多条目核心痛点、类型、前提/避坑与视频位置对照表。
3. **核心主题与学习目标**。
4. **带时间戳的章节大纲**：按逻辑结构梳理时间轴节点并附关键帧引用。
5. **知识点精讲与操作流（客观事实）**：结合画面细节与口述逻辑，每项操作与事实附 `[MM:SS]` 与 `[关键帧: frame_pts_xxx.jpg @ MM:SS]`。
6. **原始口播与字幕实录精选**：保留原始听写/字幕原文，严禁把润色稿冒充原话。
7. **专有名词与正误校对表**：对照原听写词、校对词、时间戳及关键帧/上下文依据。
8. **UP 主/博主主观观点与评价（观点区）**：明确标注 `【UP主观点】` 或 `【主观评价】`，不将个人喜好或特定环境局限写成既定事实。
9. **复习索引与要点提炼**：关键考点、排查思路与可执行结论。
10. **已知缺口与回看提示**：未听清、静默跳段或被遮挡部分如实标注时间段。
11. **AI 补充解释（独立区域）**：背景延伸、术语解释或联网核查对比，与原视频内容严格隔离（详见 `./fact-check-policy.md`）。
12. **处理来源记录**：`stableId`、原始素材、转写/抽帧参数、多模态切片核验覆盖总数与来源声明。
